7. FEE DISTRIBUTOR
============================================================

Implement a minimal, auditable FeeDistributor.

Required behavior:

When FeeDistributor receives native PW:

70% → ValidatorFeeVault
20% → Treasury
10% → Burn

The split must be deterministic.

Do not use floating-point arithmetic.

Use integer arithmetic.

The implementation must explicitly handle rounding.

============================================================
8. ROUNDING RULE
============================================================

Native PW uses integer denomination.

Define the smallest PW denomination supported by the chain.

The FeeDistributor must calculate:

validatorShare
treasuryShare
burnShare

such that:

validatorShare + treasuryShare + burnShare
=
amount received

There must NEVER be an unaccounted remainder.

Do NOT simply calculate:

70%
20%
10%

and discard rounding dust.

Any remainder must be explicitly assigned according to a documented deterministic rule.

Prefer a mathematically exact accounting rule.

Document the reason.

============================================================

17. ACCOUNTING INVARIANTS
============================================================

Implement automated invariant tests.

INVARIANT 1:

validatorShare + treasuryShare + burnShare = feeAmount

INVARIANT 2:

validatorShare = 70% of feeAmount according to the documented integer rounding rule.

INVARIANT 3:

treasuryShare = 20% of feeAmount according to the documented integer rounding rule.

INVARIANT 4:

burnShare = remaining amount after validatorShare + treasuryShare.

INVARIANT 5:

No fee routing operation creates PW.

INVARIANT 6:

No fee routing operation destroys more PW than intended.

INVARIANT 7:

No fee amount is silently retained unless explicitly documented.

INVARIANT 8:

Total PW supply does not increase.

INVARIANT 9:

FeeDistributor cannot arbitrarily transfer unrelated user funds.

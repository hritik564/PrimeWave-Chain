============================================================

You MUST investigate the current Avalanche L1 architecture and determine how PrimeWave can satisfy ALL of these simultaneously:

1. Maximum PW supply = 100,000,000.
2. PW has no arbitrary mint function.
3. 15,000,000 PW are allocated to validator/staking rewards.
4. Validators and delegators must be able to receive rewards.
5. PrimeWave must not introduce uncontrolled inflation.

- NativeTokenStakingManager

- Reward Manager
- Native Minter precompile
- P-Chain validator operations
- Initial validator set
- Subsequent validator registration
- Native token staking
- Delegation
- Uptime/reward mechanisms
- Validator weight
- Reward calculation
- Reward distribution
- Any supported mechanism for finite/preallocated reward reserves

Do NOT assume the answer.

Verify the current implementation/documentation for the exact Avalanche version being considered.

If the standard NativeTokenStakingManager requires native-token minting and therefore conflicts with the fixed 100M PW/no-mint requirement:

DO NOT silently enable inflation.

DO NOT change the tokenomics.

DO NOT remove the 15M allocation.

DO NOT invent a fake mechanism.

Instead:

1. Explain the conflict.
2. Identify technically valid alternatives.
3. Compare them.
4. Recommend the safest compatible architecture.
5. Clearly identify whether explicit PrimeWave approval is required.

10. COST-EFFECTIVE ARCHITECTURE
============================================================

Cost efficiency is a major requirement.

Do NOT recommend unnecessary infrastructure.

Prefer:

- Open-source components where secure and mature
- Existing Avalanche tooling
- Existing EVM-compatible infrastructure
- Reusable libraries
- Shared indexing/data infrastructure
- Managed infrastructure where it is cheaper and safer than self-hosting
- Automation rather than manual operations

Avoid premature development of:

- Custom wallet
- Custom bridge
- Multi-chain infrastructure
- Multiple trading pairs
- Custom oracle network
- Mobile app
- P2P marketplace
- Unnecessary microservices

The goal is:

SECURITY + COMPLETENESS + LOW OPERATING COST

not maximum complexity.

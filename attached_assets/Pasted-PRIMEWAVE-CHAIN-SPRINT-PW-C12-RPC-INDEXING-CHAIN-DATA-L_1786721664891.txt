============================================================
5. BLOCK INDEXING
============================================================

Index every PrimeWave block.

Minimum fields:

- block number
- block hash
- parent hash
- timestamp
- gas limit
- gas used
- base fee where available
- transaction count
- miner/coinbase where applicable
- state root where available
- receipts root where available

Do not assume Ethereum-specific fields exist identically on Avalanche.

Use actual RPC responses.

============================================================
6. TRANSACTION INDEXING
============================================================

Index:

- transaction hash
- block number
- block hash
- transaction index
- from
- to
- value
- gas limit
- gas price
- max fee where applicable
- priority fee where applicable
- nonce
- input/calldata
- chain ID
- transaction type where available

Support native PW transactions.

Do not decode arbitrary calldata unless the ABI is known.

============================================================
7. RECEIPT INDEXING
============================================================

Index:

- transaction hash
- status
- gas used
- cumulative gas used
- effective gas price
- contract address
- logs
- block information

Calculate:

transaction fee = gasUsed × effectiveGasPrice

where the RPC provides sufficient data.

Do not fabricate fee values.

8. LOG / EVENT INDEXING

Index all EVM logs.

Then decode known PrimeWave events where ABIs are available.

Unknown events must NOT break indexing.

============================================================
16. SYNC ENGINE
============================================================

The indexer must support:

initial sync:

block 0
→ latest

and:

incremental sync:

last indexed block
→ new blocks

Store durable sync state.

The indexer MUST be restart-safe.

If process dies at block N:

restart
→ resume safely

No duplicate records.

No missing blocks.

============================================================
17. REORG / CONSISTENCY HANDLING
============================================================

Even though PrimeWave is an Avalanche-based chain, the indexer must
still handle consistency safely.

At minimum:

- verify parent hash
- detect unexpected block replacement
- detect sync mismatch
- avoid blindly trusting local state
- support rollback/reindex of recent blocks if required

Do not implement an unnecessarily complicated Ethereum-style
deep-reorg engine.

Document the actual consistency model appropriate for PrimeWave.

We completed the live production smoke test of PWCScan and found one specific frontend defect.

DO NOT publish automatically.

The production backend/search API is working correctly, but the user-facing search results page is not interpreting valid API responses correctly.

LIVE TEST RESULTS:

1. Valid block:
   Query: 5
   API:
   /indexer-api/search?q=5
   returned:
   {
     "success": true,
     "type": "block",
     "data": {
       "number": "5"
     }
   }

   But the production UI route:
   /testnet/search?q=5
   displays:
   "No Results Found"

2. Valid transaction:
   Query:
   0xd41117d82d2978912b0f3123e866a3de123ffe71dcec31380c07e324d44544f3

   API returns the valid indexed transaction in block 5.

   But:
   /testnet/search?q=<transaction-hash>
   displays:
   "No Results Found"

3. Valid address:
   Query:
   0xb518397e3d65a0e7475635f01c225e9426a76f11

   API returns the valid address with 11 transactions.

   But:
   /testnet/search?q=<address>
   displays:
   "No Results Found"

4. Invalid query:
   definitely-not-a-real-value-xyz
   correctly displays:
   "No Results Found"

5. Direct destination pages work:
   - /testnet/blocks/5 loads Block #5
   - /testnet/tx/<valid-hash> loads the transaction
   - /testnet/address/<valid-address> loads the address

Therefore the defect appears to be specifically in the frontend search-result interpretation/rendering/routing layer.

- exact proprietary styling

Study the current Solscan UX patterns and reproduce the underlying
PRODUCT PRINCIPLES using original PrimeWave design.

Key Solscan patterns to emulate:

1. Search-first explorer navigation
2. Dense but readable data tables
3. Strong information hierarchy
4. Entity-oriented pages
5. Address pages
6. Transaction pages
7. Block pages
8. Program/contract pages
9. Validator/staking information
10. Network dashboard
11. Filters
12. Pagination
13. Human-readable transaction summaries
14. Raw/on-chain details for advanced users
15. Responsive desktop/mobile experience
16. Configurable table presentation where useful
17. Analytics-ready layout

Solscan's current homepage emphasizes network metrics, latest
transactions and dashboard navigation.

Its current account experience separates general account information
from activity, with transaction/history-style tabs.

Its transaction experience presents a concise summary first, followed
by deeper details, balance changes and raw data.

Use these PRINCIPLES.

Do not create a generic SaaS dashboard.

PWCScan should immediately feel like a serious blockchain explorer.

65. CRITICAL STOP CONDITIONS
============================================================

STOP and report if:

1. C12 API cannot support a required explorer page without inventing
data.
2. UI must fabricate blockchain information.
3. C12 data contradicts on-chain state.
4. A protocol contract must be modified purely for visual convenience.
5. PWCScan requires write access to blockchain state.
6. Private credentials are required in the frontend.
7. A serious XSS/injection vulnerability is discovered.

PRIMEWAVE TESTNET — PW-C21
PWCScan + INDEXER INTEGRATION

OBJECTIVE

PrimeWave Testnet and its core protocol have now passed PW-C20 end-to-end functional validation.

The next milestone is to make the network genuinely explorable through PWCScan.

This task is strictly:

1. Audit the existing PWCScan implementation
2. Audit the existing indexer
3. Connect the indexer to the live PrimeWave Testnet
4. Configure PWCScan against the indexer's data
5. Index historical blocks/transactions currently available
6. Verify real PrimeWave transactions appear correctly
7. Verify continuous indexing of new blocks/transactions
8. Fix integration issues required for PWCScan/indexer functionality
9. Produce a complete readiness report

DO NOT:

- recreate the blockchain
- modify genesis.json
- modify the subnet
- modify validators
- modify validator binaries
- deploy contracts
- redeploy contracts
- change Chain ID
- change Blockchain ID
- modify contract state
- modify PWSwap
- configure the domain
- configure HTTPS/TLS
- build the faucet
- expose private keys
- introduce a real signing key into the indexer
- send arbitrary diagnostic transactions

The existing PrimeWave chain is healthy and must be treated as immutable infrastructure during this task.

PHASE 2 — DEV PRIVATE KEY SECURITY
==================================================

PW-C20 found:

This is the well-known Hardhat development private key.

Audit why it exists.

Determine whether the indexer actually requires a signing key.

If it does NOT require signing:

REMOVE the DEV_PRIVATE_KEY_0 dependency.

The indexer must operate read-only against the PrimeWave RPC.

Do NOT replace it with a real private key.

- no private keys are logged

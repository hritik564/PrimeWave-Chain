6. GOVERNANCE PRINCIPLE
============================================================

There must NOT be multiple competing authorities.

The architecture must distinguish:

A. Avalanche ValidatorManager
   → authoritative validator state

B. Protocol governance
   → authorized protocol configuration

C. Emergency multisig
   → pause/unpause/freeze only

D. Timelock
   → delayed governance actions

No component should silently override another.

7. EMERGENCY MULTISIG
============================================================

Implement or integrate the 3-of-5 emergency control boundary only where necessary.

The emergency mechanism must support:

- pause
- unpause
- freeze

according to the existing governance policy.

Determine exactly what "pause" means for each relevant protocol component.

Possible components:

- FeeDistributor
- ValidatorFeeVault
- RewardVault
- ValidatorRegistry

Do NOT blindly pause everything.

For every component define:

- what operations stop
- what operations remain available
- whether claims remain available
- whether fee receipt remains available
- whether funds remain withdrawable
- whether the emergency action is reversible

Document this precisely.

9. 3-OF-5 SECURITY
============================================================

The emergency mechanism must require:

3 approvals out of 5 authorized signers.

Test:

- 1 signer → fail
- 2 signers → fail
- 3 signers → succeed
- 4 signers → succeed
- 5 signers → succeed
- duplicate signer approval → must not count twice
- unauthorized signer → fail
- replayed execution → fail

Use development-only keys.

DO NOT generate production keys.

11. 48-HOUR TIMELOCK
============================================================

Integrate the approved 48-hour timelock where the governance policy requires it.

Use:

48 hours = 172,800 seconds

But do not simply add a generic timelock to every function.

Use the exact action list from:

docs/PRIMEWAVE_GOVERNANCE_POLICY.md

For each timelocked operation:

1. queue
2. wait minimum delay
3. execute
4. emit appropriate events

Test:

- execution before 48h → fail
- execution at/after valid delay → succeed
- cancellation if permitted → correct behavior
- duplicate execution → fail
- altered parameters → fail
- replay → fail

12. TIMELOCK IMMUTABILITY
============================================================
